# Generic ACP Agent — Progress

## Done

- **Project scaffold** — TypeScript (`type: module`), `tsconfig.json` (NodeNext), builds with `tsc`.
- **Dependencies** — `@agentclientprotocol/sdk` (the maintained successor of `@zed-industries/agent-client-protocol`, which is deprecated) and `openai`.
- **`src/config/config.ts`** — `loadConfig()` resolves `{ baseUrl, apiKey, model }`:
  - from `GENERIC_ACP_CONFIG` env var (path to a JSON file), falling back to `./config.json` in the cwd
  - individual env vars `GENERIC_ACP_BASE_URL` / `GENERIC_ACP_API_KEY` / `GENERIC_ACP_MODEL` override the file
  - throws a clear error naming exactly which fields are missing if none of the above supply them
  - called once at startup in `main.ts`
- **`src/acp/agent.ts`** — `GenericAcpAgent` implements the ACP `Agent` interface:
  - `initialize` — advertises protocol version 1 and prompt capabilities (text + embedded context + image; audio when `audioSupport` is on)
  - `authenticate` — no-op (auth is handled via the configured API key, not ACP auth methods)
  - `newSession` — creates a session, stores `cwd` and `mcpServers`
  - `prompt` — appends the user message, streams the model's reply back as `agent_message_chunk` session updates, appends the assistant reply to history, returns `stopReason: "end_turn"` (or `"cancelled"`)
  - `cancel` — aborts the in-flight request for a session via `AbortController`
- **`src/acp/session.ts` / `content.ts`** — in-memory `SessionStore` keyed by session id; `contentBlocksToText()` converts ACP `ContentBlock[]` (text / resource_link / resource) into a plain string for the OpenAI message history.
- **`src/openai/provider.ts` / `streaming.ts`** — `OpenAiProvider` wraps the `openai` SDK client (pointed at any OpenAI-compatible `baseUrl`) and streams chat completion deltas as an async generator.
- **Tool calling** — `src/openai/streaming.ts` streams `tool_call` deltas; `src/openai/tools.ts` defines the built-in `read_file` / `write_file` / `run_terminal` tools; `src/acp/agent.ts` runs the full tool-call loop (accumulate deltas → `tool_call` session update → `requestPermission` → execute via client capabilities → feed result back as a `tool` message, up to 10 iterations).
- **MCP bridging** — `src/mcp/client.ts` wraps the MCP SDK `Client` + `StdioClientTransport` (connect / listTools / callTool / close); `src/mcp/bridge.ts` aggregates servers, namespaces tools as `serverName_toolName`, and routes calls; `newSession` connects stdio, HTTP, SSE, and ACP MCP servers and leaves the bridge up across `session/cancel` (cancel aborts the turn only); `src/openai/tools.ts` `getTools()` merges built-in + MCP tools. Verified over stdio with a mock MCP server (tool discovery, call routing, failure isolation) and by `test/integration/agent.test.ts` (tools still listed on the prompt after cancel).
- **Error handling polish** — `src/errors.ts` classifies OpenAI SDK errors (`auth` / `rate_limit` with `retry-after` / `network` / `model` / `unknown`) and logs them with session context; `prompt()` in `src/acp/agent.ts` now sends an `[Error: …]` `agent_message_chunk` and returns `end_turn` instead of rethrowing. Published via session updates since ACP v1 has no `error` stop reason or `errorMessage` field (openai v7 has no `APIStatusError`; `APIError` is the base). Verified end-to-end over stdio against a 401 mock provider.
- **`config.example.json`** — sample config matching the readme's provider examples (now includes `apiMode` and `responseSchema`).
- **Structured output / Responses API** — `src/openai/streaming.ts` accepts an optional `response_format` and retries without it (with a warning) when a provider rejects it; `src/config/config.ts` adds `apiMode` (`"chat-completions"` default / `"responses"`) and `responseSchema` (config or `GENERIC_ACP_API_MODE` / `GENERIC_ACP_RESPONSE_SCHEMA` env), validated at startup; `src/openai/responses.ts` streams `/v1/responses` (maps `output_text.delta` → text, `function_call*` events → `tool_call`, `response.completed`/`incomplete` → finish reason) and converts chat history to `ResponseInputItem[]`; `src/openai/tools.ts` maps `ChatCompletionTool` → Responses `FunctionTool`; `src/openai/provider.ts` dispatches on `apiMode` and falls back from `/v1/responses` to chat completions when a provider returns 404 / unsupported. Verified end-to-end over stdio with a mock Responses provider (streaming + a `mock_add` tool call executed through MCP) and a mock provider that rejects `response_format`.
- **Image content blocks** — `src/acp/content.ts` gains `contentBlocksToMessageContent()` which maps ACP `ContentBlock[]` into OpenAI multi-part message content (`text` / `image` → `{type:"image_url", image_url:{url:"data:<mime>;base64,<data>"}}` / `resource_link` / `resource`), returning a plain string for pure-text prompts; `src/acp/agent.ts` advertises `image: true` in `promptCapabilities` and uses the new mapper in `prompt()`, falling back to `contentBlocksToText()` when `imageSupport` is disabled; `src/config/config.ts` adds `imageSupport` (default `true`, env `GENERIC_ACP_SUPPORT_IMAGES`); `src/openai/responses.ts` maps image parts to `input_image` for Responses mode. `streaming.ts` needed no change — `ChatCompletionMessageParam["content"]` already accepts string-or-parts. Verified end-to-end over stdio with a mock provider in three modes (chat-completions parts, `imageSupport=false` text flattening, Responses `input_image`), plus the MCP bridge regressions — see `scripts/test-image-content.ts`.
- **Session load** — `src/acp/agent.ts` now advertises `loadSession: true` and implements `loadSession()`: looks up the session by id (unknown id → resource-not-found error), rejects a mismatched `cwd`, reconnects the MCP bridge when it is null, and streams the stored history back to the client as `session/update` notifications (`user_message_chunk` per user message + `agent_message_chunk` per assistant message with `messageId: "load-<n>"`, plus a `tool_call` update for each stored tool call). The SDK `LoadSessionResponse` has no `messages`/`sessionId` fields, so history is replayed via notifications. `src/acp/content.ts` gains `messageContentToContentBlocks()` (OpenAI message content → ACP `ContentBlock[]`, inverse of `contentBlocksToMessageContent()`); `src/acp/session.ts` adds a 1h memory TTL (`lastActivityAt` + lazy prune on create). When `sessionDir` is set, the same store writes JSON and reloads it after the process restarts (see the settings bullet below). Verified end-to-end over stdio with a mock provider (replay as notifications, history preserved across load, wrong-cwd and unknown-id errors), and all prior regressions (`test-image-content`, `test-mcp-bridge`, `test-failure`) still pass — see `scripts/test-session-load.ts`. A correction was made to spec 03: the earlier draft Response-shape example (`messages`/`sessionId` in the body) does not match the SDK types.
- **Real-world validation (partial)** — provider-independent edge cases verified over stdio with a mock provider in `scripts/test-edge-cases.ts`: concurrent sessions never interleave messages, a 300×300-char streamed response arrives untruncated (90000 chars, history retained), a 10-turn conversation accumulates history, and a mid-stream socket drop streams the partial text then reports `[Error: …]` and the session recovers. `src/errors.ts` now classifies mid-stream drops (`TypeError: terminated` / `UND_ERR_SOCKET`) as `network` instead of `unknown`. **First live provider validated: LM Studio at `http://10.211.67.199:1234/v1` (no key), model `qwen3.6-27b-mtp`** — `scripts/validate-real-provider.ts` confirmed text + streaming + history accumulation (`end_turn`, turn-2 verbatim repeat), and `scripts/validate-tools-real-provider.ts` confirmed the full tool-call loop against the live model (`read_file` → `requestPermission` → `fs/read_text_file` → final answer). **Second provider validated: OpenCode Zen (hosted free tier) at `https://opencode.ai/zen/v1`, model `big-pickle`** — the free tier gate-keeps by client identity (`400 MissingSessionID` without the opencode `User-Agent` + `x-opencode-session: public`), so `src/config/config.ts` gained `AgentConfig.headers` (config-file `headers` or `GENERIC_ACP_HEADERS` JSON env) and `src/openai/provider.ts` passes it as the openai client's `defaultHeaders` (merged after the SDK's own UA, so the override lands on the wire); with it, text + streaming + history (735-char verbatim turn-2 repeat) and the full tool loop passed. That live run found and fixed a real conformance bug: the `requestPermission` `toolCall` omitted `title` (clients would show "undefined" in the permission UI); `src/acp/agent.ts` now sends the title. `PROVIDERS.md` documents per-provider configs (including the zen header recipe + PowerShell `provider.ENV` workflow), the results matrix, run instructions, and known quirks (e.g. Azure's `api-version`). **Third provider validated: OpenRouter at `https://openrouter.ai/api/v1`, model `ling-3.0-flash-vl:free`** — full tool loop passed first try (`read_file` → permission → real `package.json` → `completed` → "generic-acp-agent", `end_turn`), and a plain-prompt run showed clean degradation when the model unexpectedly requested a tool but the driving script registered no `session/request_permission` handler (agent masks it as an `[Error: …]` message, no crash; turn 2 then streamed a real 743-char answer). No extra config needed (extension-free OpenRouter works with the plain client). OpenAI, Azure, and the JetBrains UI are still open — see the To do section.
- **End-to-end smoke test** (manual, not automated) — built the project, ran it over stdio against a mock OpenAI-compatible streaming server, and confirmed `initialize` → `session/new` → `session/prompt` correctly streams chunks and resolves with `end_turn`.
- **Protocol conformance — omitted fields (Task 9)** — `src/acp/agent.ts` now sends every schema field real clients render: `agentInfo` (`name` + version read from package.json) in `initialize`; per-turn assistant `messageId` on streamed `agent_message_chunk`s (`session.nextAssistantMessageId()`); reasoning deltas streamed as `agent_thought_chunk` sharing the message's id (`streaming.ts` yields `reasoning`, `responses.ts` maps `reasoning_text`); `rawInput`/`rawOutput`/`name` on pending, permission-request, and completed tool calls; `locations` (`resolve(cwd, args.path)`) for `read_file`/`write_file`; `PromptResponse.usage` captured from the stream `done` delta (`stream_options.include_usage` with a retry fallback for rejecting providers, plus Responses-mode usage); and failing tool executions now report `status: "failed"` instead of `completed`. `executeTool` throws `Unknown tool: <name>`. Verified by the new `scripts/test-conformance.ts` (24 assertions, all passing) plus all existing mock regressions and a live 2-turn OpenRouter run — see `progres/09-protocol-conformance.md`.

- **Turn control** — `src/openai/streaming.ts` retries a chat completion only for HTTP 400/422, drops `stream_options.include_usage` before `response_format`, and does not retry auth, network, or 5xx. `src/acp/agent.ts` `cancel` aborts permission and terminal waits (`terminal.kill()`), writes `Cancelled.` tool results for unanswered calls, and does not close MCP. `src/openai/responses.ts` keeps assistant text next to `function_call` items. Finish reason `length` maps to `max_tokens` and `content_filter` maps to `refusal`.
- **Session robustness** — `prompt()` rejects a second turn while one is running; a failed stream keeps the partial assistant text (and an `[Error: …]` chunk with `messageId`) in history; invalid tool JSON fails the tool call instead of running with `{}`. `responseSchema` is sent as Responses `text.format`, with a 400/422 retry that drops only the schema. Expired sessions and `session/close` close the MCP bridge. `session/load` replays tool `status` and `locations`, and reconnects when the MCP server list changes. HTTP, SSE, and ACP MCP servers are launched (`src/mcp/bridge.ts`, `src/mcp/acp-transport.ts`) and advertised on `initialize`. `src/main.ts` starts with `#!/usr/bin/env node`.
- **Model context before the call** — `src/openai/model-info.ts` reads the context window from the model record (`loaded_context_length`, or `context_length` / `max_context_length` / `max_model_len` on `/v1/models`, otherwise the same host's `/api/v0/models`). `GENERIC_ACP_CONTEXT_TOKENS` overrides it. `src/openai/context.ts` `applyContextLimit()` shrinks the payload before `chat.completions`, and does not send the request when it still cannot fit.
- **Long local inference** — `src/openai/http.ts` sets the OpenAI client timeout and undici `headersTimeout` / `bodyTimeout` together (default 30 minutes, `GENERIC_ACP_REQUEST_TIMEOUT_MS` or `requestTimeoutMs`). Node's fetch otherwise closes a silent socket after five minutes, which a long prefill reports as a dropped stream. `src/errors.ts` names that inactivity timeout separately from a socket reset.
- **Automated tests (Task 8)** — `npm test` builds with `tsc` then runs Vitest. Unit tests cover `config`, `content`, `session`, `errors`, chat-completions retry (`streaming.test.ts`), and Responses history (`responses.test.ts`). `test/integration/agent.test.ts` drives `GenericAcpAgent` for stop-reason mapping, permission cancel, terminal kill, and MCP survival across cancel. `test/integration/stdio-scripts.test.ts` runs the existing mock stdio scripts (`test-conformance`, `test-edge-cases`, `test-session-load`, `test-image-content`, `test-mcp-bridge`, `test-failure`). `npm run test:coverage` (`vitest.config.ts`, `@vitest/coverage-v8`) requires 70% statement and line coverage of `src/` except `src/main.ts`.
- **Several endpoints in one process** — `src/config/endpoints.ts` reads `endpoints` or `GENERIC_ACP_ENDPOINTS`. `src/acp/agent.ts` keeps one `OpenAiProvider` per endpoint. With two or more, the model option is `endpointId:modelId` and the chat goes to that client; a single endpoint still shows bare model ids. One catalog failure leaves the other endpoints listed.
- **Settings and standard OpenAI fields (Tasks 10–17)** — `src/config/settings.ts` reads sampling and instruction fields (`instructions`, `temperature`, `top_p`, `maxTokens`, `stop`, `seed`, penalties, `tool_choice`, `parallel_tool_calls`, `reasoning_effort`, image `detail`) from config or `GENERIC_ACP_*`. `src/openai/sampling.ts` sends them on chat completions and Responses, and drops a rejected field the same way `response_format` is dropped. `src/acp/controls.ts` advertises `model` (from `GET /v1/models` via `src/openai/model-info.ts`), `tool_choice`, `reasoning_effort`, `image_detail`, and `parallel_tool_calls` when the client supports boolean options. Modes (`GENERIC_ACP_MODES`) apply through `session/set_mode`. Slash commands (`GENERIC_ACP_COMMANDS`) are an `available_commands_update` and a `/name` prefix. `includeOpenDocuments` attaches editor text from `src/acp/documents.ts`. `audioSupport` maps audio to `input_audio` and retries once without it. `usage_update` is emitted when the stream reports usage and the context window is known. `sessionDir` persists sessions as JSON (`src/acp/session.ts`); `initialize` advertises list, delete, resume, fork, and close. Unstable providers list the configured OpenAI-compatible endpoint and refuse to disable it. Covered by `test/unit/features.test.ts`.
